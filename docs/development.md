# Developer guide

This repository builds the org's website, the "Colony Arena" at
<https://swarm-routing.github.io/>: the hub and one page per project
(generated by Python from `site/hub/projects.json`), the `/pipeline/` page,
and AntHocNet's browser game, docs and API under `/AntHocNet/`. The game runs
AntHocNet's own C++ `core/` compiled to WebAssembly, built from the AntHocNet
commit pinned in `protocols.lock`. This page shows how to set up, build,
test and lint the site, and what CI checks. The rules a change must keep are
in [AGENTS.md](../AGENTS.md) ("Golden rules": no routing logic in the site,
deterministic browser simulations); how the core reaches the browser is
[pipeline.md](pipeline.md); how issues and pull requests work is in the
org's [CONTRIBUTING.md](https://github.com/swarm-routing/.github/blob/main/CONTRIBUTING.md).

## Prerequisites

| Tool | Version | Needed for |
| --- | --- | --- |
| Linux or macOS, `git`, `make`, `bash` | any recent | everything |
| Python | 3.11 or newer | the hub, the project pages, every check |
| Node.js | 22 | the browser smokes and AntHocNet's web tests |
| emsdk (Emscripten) | 4.0.10, AntHocNet's pin (`.github/actions/setup-emsdk` there) | the full site: the game's WebAssembly core |
| mkdocs-material | AntHocNet's pin (`requirements/mkdocs-material.txt` there) | the full site: AntHocNet's docs |
| doxygen | any recent (CI: Ubuntu 24.04's) | the full site: AntHocNet's API |
| C++ compiler and CMake | GCC 13 / CMake 3.20 or newer | the parity check's native side |
| actionlint | 1.7.12 (`pip install actionlint-py==1.7.12.25`) | `make lint` |

The hub and project pages need Python alone; everything under `/AntHocNet/`
needs the rest.

## Get the code

```bash
git clone https://github.com/swarm-routing/swarm-routing.github.io.git
cd swarm-routing.github.io
```

There are no submodules. `tools/build-site.sh` clones AntHocNet itself at
the pinned commit (into `build/src/AntHocNet`); set `AHN_SRC` to the path of
a checkout you already have to reuse it. The build replaces that checkout's
`web/` with `site/anthocnet/` (it deletes `web/` first), so use a disposable
checkout, never one with work of your own in `web/`.

## Dependencies

- **AntHocNet** comes from the commit in `protocols.lock` (protocol, repo,
  40-character commit, tag; `python3 tools/lock.py AntHocNet commit` reads
  it). A newer core, docs or API reaches the site only through a PR that
  bumps that line; `release-sync.yml` opens one when AntHocNet releases.
  `site/anthocnet/` is AntHocNet's browser adapter and game, overlaid onto
  that checkout as its `web/`.
- **Browser test tools**: `playwright-core` and `axe-core`, pinned in
  `site/anthocnet/test/browser-tools/package-lock.json`, installed with
  `npm ci` in a scratch directory (see "Test").
- **Leaderboard data** (planned, #12) will come from swarm-routing/benchmarks,
  regenerated by a script, never typed. The vcpkg plan
  (swarm-routing/.github#489) does not change how the site is built.

## Build

The hub and project spaces only (Python alone, under a second):

```bash
SKIP_ANTHOCNET=1 tools/build-site.sh build/hub
python3 -m http.server -d build/hub 8000   # then open http://localhost:8000/
```

The whole site, as Pages serves it (needs emsdk activated, mkdocs-material
and doxygen):

```bash
source /path/to/emsdk/emsdk_env.sh
make build                  # tools/build-site.sh build/site
python3 -m http.server -d build/site 8000
```

## Test

| What | Command | CI |
| --- | --- | --- |
| the tools' self-tests and the design-token check | `make test` (plus `python3 tools/stamp_build.py --self-test`, `python3 tools/release_sync.py --self-test` and `bash -n tools/bot_pr.sh`, as CI) | `Build, parity, crawl, smoke + axe` |
| the hub crawl: links, statuses, the one top bar | `python3 tools/check_hub.py build/hub` (or `build/site`) | same |
| native vs WebAssembly decision traces, byte-identical | `(cd build/src/AntHocNet && web/test/parity.sh 120 "1 2 7 42")` after a full build | same |
| AntHocNet's web tests and site checks (xray, quest parser, i18n, the Nest chambers, bench, experiment, levels, labs) | the block after this table, after a full build into `build/site` | same |
| the browser smokes with axe, day and night | see below | same |

AntHocNet's web tests and site checks, as `pages.yml` runs them, from the
repository root (the subshell stops at the first failure):

```bash
(
  site="$PWD/build/site/AntHocNet"
  cd build/src/AntHocNet || exit 1
  node web/test/xray.test.mjs &&
  node web/test/quest.test.mjs &&
  python3 web/tools/i18n-check.py &&
  python3 tools/checks/check-site-links.py &&
  for t in bench.test experiment.test levels labs; do
    node "web/test/$t.mjs" "$site" || exit 1
  done
)
```

The browser smokes use the pinned tools from a scratch directory:

```bash
repo=$PWD; pw=$(mktemp -d)
cp site/anthocnet/test/browser-tools/package.json site/anthocnet/test/browser-tools/package-lock.json "$pw/"
(cd "$pw" && npm ci --no-audit --no-fund && npx --no-install playwright-core install chromium \
  && node "$repo/site/anthocnet/test/smoke.mjs" "$repo/build/site/AntHocNet" \
  && node "$repo/test/hub-smoke.mjs" "$repo/build/site")
```

`make test` and the hub crawl run with Python alone; parity, the web tests
and the smokes need the full build. On `main`, CI also deploys and then
smoke-tests the live site.

## Run

The site is static: build it (see "Build") and serve the directory with any
static server, as above. Changes to a project's facts go in
`site/hub/projects.json` (public repositories only; `render_hub.py` refuses
others), with the source cited (that repository's AGENTS.md or roadmap);
never a benchmark number typed by hand. A change to the game is a change
under `site/anthocnet/`; the `learn-site` skill in `.claude/skills/` has the
full procedure (parity, smokes, README figures).

## Docker and dev containers

The site needs no Docker image of its own; the `make shell` target opens a
shell in `ghcr.io/swarm-routing/ns3-dev:latest-debug` with this checkout at
`/src`, which has Python and a C++ toolchain but not emsdk. There is no
`.devcontainer/`.

## Lint and format

```bash
make lint      # actionlint
python3 tools/check_tokens.py   # no colour, radius or font outside site/anthocnet/shell/tokens.css
make headers   # licence headers (fetches the org tools)
make org-sync-check
make check     # lint, test, headers and org-sync together
```

There is no code formatter for the site's HTML, CSS and JavaScript.

## CI map

| Workflow | Job (check name) | What it checks | Required |
| --- | --- | --- | --- |
| `pages.yml` | `Build, parity, crawl, smoke + axe` | the self-tests, the full build at the pinned AntHocNet commit, parity, AntHocNet's web tests, the crawls, the browser smokes with axe | yes |
| `pages.yml` | `Deploy to Pages`, `Smoke the live site` | on `main` only: deploy, then smoke the live pages (a red live smoke opens an issue) | no |
| `licence.yml` | `headers / licence` | licence headers | yes |
| `release-sync.yml` | | on an org release: redeploy, regenerate `data/hub.json`, bump `protocols.lock`, open a `[release-sync]` issue | no (event-driven) |
| `org-sync.yml` | `check / org-sync` | the org-managed files match the templates | yes |
| `pr-title.yml` | `title / title` | the PR title is a lowercase Conventional Commit | yes |
| `review-gate.yml` | `review / coderabbit` | CodeRabbit has reviewed the PR | yes |
| `dco.yml`, `scorecard.yml`, `sync-labels.yml` | | sign-off on outside contributions; OpenSSF Scorecard; labels | no |

The required checks are the ones the `main` ruleset lists: `gh api
repos/swarm-routing/swarm-routing.github.io/rules/branches/main`. `main` merges through a merge queue, so a pull request is merged by
enabling auto-merge. AntHocNet's own CI also fetches `site/anthocnet/` and
runs the parity check against it, so a change there can turn an AntHocNet
`core/` PR red.

## Release

The site has no versioned releases: every merge to `main` deploys. The
org's procedure for the repositories that release, whose releases reach the
site through `release-sync.yml`, is [CONTRIBUTING "Cutting a release"](https://github.com/swarm-routing/.github/blob/main/CONTRIBUTING.md#cutting-a-release).

## Troubleshooting

- **The parity check fails.** The browser build is no longer byte-identical
  to native: randomness must be drawn into named locals, mobility must avoid
  libm trigonometry, and `-ffp-contract=off` must stay (golden rule 11).
- **`emcc: command not found` during a full build.** Activate emsdk first
  (`source <emsdk>/emsdk_env.sh`), at version 4.0.10.
- **mkdocs fails with an unknown theme or plugin.** Install AntHocNet's
  pinned requirements: `pip install --require-hashes -r
  build/src/AntHocNet/requirements/mkdocs-material.txt`.
- **`render_hub.py` refuses a project.** Only public repositories may appear
  on the site.
- **`check_tokens.py` fails.** A colour, radius or font was written outside
  `site/anthocnet/shell/tokens.css`; use a token.
- **The smoke cannot launch Chromium.** Run `npx --no-install playwright-core
  install chromium` in the scratch directory (with `--with-deps` on a bare
  Linux system, as CI does).
